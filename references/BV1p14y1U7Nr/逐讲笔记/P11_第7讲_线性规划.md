# P11 第7讲：线性规划

已逐段阅读476段AI字幕（5556字，1.20—1130.86秒），查看12点联系图，细读04、09、11号720p公式图。方法、分支、输入输出及检查见[M07](../方法步骤/M07_线性规划.md)。

## 从评价问题转为资源优化

前几讲多为给已有方案评分；本讲直接决定资源如何分配。先定义决策变量，再从文字条件写目标和约束，最后转成求解器格式。线性指未知变量的一次线性组合，系数是给定数；不是因为调用linprog，任何目标都会自动变成线性。

## 例一：六个人与1200发资源

课程设两种任务数量x1、x2，最大化$40x_1+30x_2$，要求人数和≤6，资源消耗$240x_1+120x_2\le1200$，并给出每项至少1人。后者是课程额外任务假设，不是“人数”天然必须≥1。

按M07-S02-B把目标系数改为(-40,-30)，按S03/S04把下界与资源约束整理成矩阵，再求最小值，原最大值取返回值的负数。实际补充求解得到x=(4,2)、最小值-220、原目标220；人数与资源均用尽。

[补充程序](../工具/P11_求解核对.py)复用D盘已安装SciPy，记录成功状态和约束余量；[结果JSON](../原始材料/P11/补充求解核对.json)还包括小规模整数枚举与另一标准型例子的核对，没有安装新依赖或执行教师MATLAB。人数本应取整数，本例连续松弛最优恰好是整数，不能由此推广到所有人员分配题。

课程用拉格朗日把两条资源约束取等，得到同一个点。一般问题不能默认全部不等式都紧，更不能把任意驻点称为最优。这里可补充证明：$40x_1+30x_2=20(x_1+x_2)+10(2x_1+x_2)\le220$，而(4,2)达到该界，因此结论有全局最优依据。

## 标准型的每个选择

| 原题条件 | 转换规则 | 必须检查 |
| --- | --- | --- |
| 最大化$c^Tx$ | 最小化$-c^Tx$ | 求解后只恢复目标符号，不翻转x |
| 最小化$c^Tx$ | 直接输入c | 变量顺序与约束一致 |
| 约束≥ | 系数与右端同时乘-1，变≤ | 不漏右端负号 |
| 约束≤ | 直接作为A/b行 | 资源单位与目标单位不混 |
| 约束= | 放Aeq/beq | 不随意当不等式或假定其他约束也取等 |
| 无该类约束 | 成对参数`[]` | 空约束与零约束不同 |
| 无有限上下界 | 对应下界-Inf、上界Inf | 不把下界也写+Inf |

[05:10清晰图](https://www.bilibili.com/video/BV1p14y1U7Nr/?p=11&t=310)的三变量转换例已逐项核对。补充求解x约(6.428571,.571429,0)，原最大值约14.571429，等式残差0；该数值是补充验证，不是本讲课件显示的求解结果。

[MathWorks linprog](https://www.mathworks.com/help/optim/ug/linprog.html)确认该接口采用最小化标准。课程“MATLAB只能求最小值”应限定为当前接口表示，不能泛化为整个软件没有最大化建模能力。

## 例二：两个目标转为带风险上限的单目标

13:30画面给出四种资产的收益率、风险损失率、交易费率，另有银行利率5%、无风险费与交易费。用银行x0和四项资产投入x1至x4统一按资金单位建模，净收益为$\sum(r_i-p_i)x_i$，预算含$\sum(1+p_i)x_i=M$。

本例风险特定定义为最大单项$q_ix_i/M$。课程选定可接受上限a，把“风险尽量小”变成每项$q_ix_i\le Ma$，然后只最大化净收益。不能把它改成总风险求和，也不能漏银行变量、漏交易费或把百分数28直接当28倍收益。

这是一种明确选择偏好的建模方式，不会自动同时实现两个目标各自最优。改变阈值a应重算并比较；P11未给出M和a具体数值，暂不生成数值投入方案。课堂代理风险也不是对真实金融风险的完整刻画。

## 求解后怎样判断

检查约束、上下界、原目标符号和求解状态，再解释变量的业务意义。不可行、目标无界和有多个有限最优解是不同情况，不能统称“无穷解”，更不能仅用矩阵秩判断所有优化结论。课程返回x不是普遍意义的无约束驻点；线性目标最优常出现在边界。

## 自测

- 目标系数变负后，解x也要变负吗？——不用，只恢复原目标值符号。
- 最优解用了全部资源，是否可提前把所有≤改为=？——不能，要先验证活跃约束或用正确优化求解。
- 人数LP返回3.5怎么办？——不能随意四舍五入，需按整数模型求解。
- 风险上限选择后还在同时最小化风险吗？——当前模型只保证上限，优化的是净收益。
- Solver给出一个向量就算完成吗？——还需看状态、残差与业务可行性。
