# 课程材料与 bili-note 衔接

## 选择可用入口

本 skill 负责课程教学分析，不内置 B站下载器。取得材料与分析材料可以分别进行。

1. 有本地字幕、讲义或代码时直接分析；SRT/VTT 保留时间段，字幕 JSON 依据实际键值解析，不预设所有文件都同一结构。不能把当前分块的一段字幕当作全课。
2. 需要在线材料且 `bili-note` 可用时，读取其完整 `SKILL.md`，只调用其实际存在且参数匹配的脚本。按技能根路径解析脚本位置，不依赖当前工作目录；Python 使用本机可执行的解释器，避开无法启动的 Windows 商店别名。
3. `bili-note` 不在可用列表时，在实际技能目录查找；找不到则明确说明没有提取器，使用当前可用的公开浏览工具读取能访问的材料或请用户提供字幕/讲义。标题和简介只能用于制定学习计划。

## 使用 bili-note 时的操作边界

以当前安装版本为准，不在此维护重复的命令和接口参数。

- 其当前文档要求联网/登录态使用 `web-access`。先确认该能力实际可用；缺失时不要虚构工具、绕读 Cookie 或声称已成功调用。可继续分析本地材料，或向用户说明在线提取路线缺少的依赖。
- 当前视频流程要求先做轻量预检，再取得本次关键帧视觉理解的 `on/off` 选择；用户已经明确给出的本次选择可直接使用，不能替用户猜测。需要提问时说明这是所用 `bili-note/SKILL.md` 的要求，并说明视觉输入的影响。
- 只抓取用户范围内的材料；评论仅在用户需要时抓取。评论可以提供纠错线索，不能自动当作权威结论。
- 自动字幕不可得不等于没有字幕：按该 skill 指南检查网页 AI 字幕与转写路线。缺失增强能力时保留可用材料，不默认安装 ASR 模型或下载整套视频。
- 不强制结束浏览器，不复制登录资料，不因创建分析笔记扩大为账号或环境配置操作。

## 对接材料包

提取完成后，先读运行报告与实际文件清单，确认当前包结构。常见材料如下，缺失时如实记录：

| 材料 | 用途 |
| --- | --- |
| `indexes/字幕全集.md` / `.jsonl` | 定位知识模块和字幕时间段 |
| `subtitles/srt/` 或原始字幕 JSON | 回查时间与上下文 |
| `indexes/证据索引.jsonl` | 建立分析结论的来源映射 |
| `metadata/note_budget.json` | 读取画面依赖提示和笔记粒度建议 |
| `metadata/keyframes_manifest.json`、视觉观察文件 | 找到已实际查看的画面证据 |
| 课程讲义、原始代码和数据 | 核对公式、题目与数值结果 |

开启关键帧理解时先看联系图，再打开公式或代码对应的清晰单帧。联系图看不清的公式仍视为未知；OCR 是辅助识别，关键符号需要核对。

若调用完整 bili-note 写笔记流程，遵循其写前预算和写后验收；若本次只用已经存在的材料包回答局部课程问题，按用户问题控制篇幅，不为凑字数扩写。热度、字数和引用比例不能证明数学结论正确。

## 来源记录

至少记录可得的课程标题、UP主、URL/BV号、请求范围、分析日期、分P状态、材料类型和材料路径。未知元数据写“未取得”，不猜测发布时间或作者。

将“材料取得成功”和“材料已阅读分析”分开计数。多P合并时每个证据保留其原分P，不能把 P2 的时间附到 P1。
